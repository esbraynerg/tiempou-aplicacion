Este documento identifica todos los archivos previstos para la construcción de TiempoU.

Su finalidad es establecer:

- Nombre de cada archivo.
- Ubicación dentro del repositorio.
- Responsabilidad específica.
- Relación con otros archivos.
- Orden de construcción.

Este inventario complementa la arquitectura técnica y servirá como control durante el desarrollo.

# 4. RESPONSABILIDADES Y DEPENDENCIAS

Las siguientes reglas serán obligatorias:

1. Las páginas utilizarán componentes reutilizables.
2. Los componentes no duplicarán cálculos académicos.
3. Los servicios utilizarán las funciones de lib cuando necesiten realizar cálculos.
4. Los servicios actualizarán la información mediante el estado central.
5. Las páginas recibirán información del estado central.
6. initialData.js será la fuente de los datos iniciales.
7. AppProvider.jsx administrará los datos durante la sesión.
8. Los estilos compartidos estarán centralizados.
9. Las operaciones relacionadas deberán actualizar todas las vistas afectadas.
10. Ningún archivo podrá introducir una estructura de datos incompatible con la establecida.

# 5. REGLAS PARA LA GENERACIÓN DE ARCHIVOS

Cada archivo generado deberá cumplir los siguientes requisitos:

- Código completo.
- Nombre y ubicación exactos.
- Importaciones correctas.
- Exportaciones correctamente definidas.
- Compatibilidad con los demás módulos.
- Responsabilidad claramente delimitada.
- Sin funciones duplicadas.
- Sin referencias a archivos inexistentes.

Cuando se modifique un archivo, se revisarán sus dependencias.

No se entregarán fragmentos incompletos para reemplazar partes de archivos sin instrucciones precisas.

# 6. CONTROL DE CONSTRUCCIÓN

Los archivos se marcarán como:

PENDIENTE:
Todavía no generado.

GENERADO:
Código creado y entregado.

INTEGRADO:
Conectado con sus dependencias.

VERIFICADO:
Revisado junto con los módulos relacionados.

La existencia de un archivo no significa que esté terminado.

# 7. CONTROL DE CAMBIOS

Si durante el desarrollo se identifica la necesidad de incorporar un nuevo archivo:

1. Se explicará su finalidad.
2. Se determinará su ubicación.
3. Se identificarán sus dependencias.
4. Se actualizará este inventario.
5. Se verificará que no duplique responsabilidades existentes.

No se agregarán archivos sin justificación técnica.

# 8. CRITERIO DE FINALIZACIÓN

El inventario se considerará completado cuando todos los archivos necesarios estén generados, integrados y verificados.

La aplicación completa deberá poder ejecutarse con sus dependencias correctamente configuradas y demostrar las funcionalidades aprobadas de TiempoU.
