# ESPECIFICACIÓN DE DISPONIBILIDAD Y SESIONES – TIEMPOU

## 1. Objetivo

Este documento define cómo TiempoU registra las horas libres del estudiante y cómo utiliza esa información para distribuir el esfuerzo de las actividades en sesiones de estudio.

El propósito es ayudar al estudiante a organizar sus actividades académicas de acuerdo con el tiempo que realmente tiene disponible.

## 2. Configuración de disponibilidad

La aplicación debe incluir una sección independiente llamada Disponibilidad.

El estudiante configura sus horas libres para cada día de la semana.

No es necesario registrar por separado los horarios de clases, trabajo u otras obligaciones. El estudiante únicamente registra los intervalos en los que puede estudiar.

### 2.1. Registro de intervalos

Para cada día de la semana se podrán agregar uno o varios intervalos de disponibilidad.

Cada intervalo contiene:

- Hora de inicio.
- Hora de finalización.

Ejemplo:

| Día | Inicio | Finalización |
|---|---|---|
| Lunes | 18:00 | 20:00 |
| Martes | 19:00 | 21:00 |
| Miércoles | 17:00 | 20:00 |
| Jueves | Sin disponibilidad | |
| Viernes | 18:00 | 21:00 |
| Sábado | 08:00 | 11:00 |
| Domingo | 09:00 | 12:00 |

### 2.2. Validaciones

- La hora de inicio debe ser anterior a la hora de finalización.
- No se permiten intervalos duplicados o superpuestos.
- No se permiten intervalos de duración cero.
- Se pueden registrar varios intervalos en un mismo día.
- Los días sin intervalos se consideran días sin disponibilidad.
- La aplicación debe permitir modificar y eliminar intervalos.

### 2.3. Guardar disponibilidad

Los cambios realizados en la configuración no deben recalcular inmediatamente las sesiones mientras el estudiante sigue editando.

El botón Guardar aplica los cambios.

Después de guardar:

- Se actualiza la disponibilidad.
- Se recalculan las variables del motor IPA que dependan de ella.
- Se actualiza el orden de prioridad.
- Se reorganizan las sesiones futuras cuando corresponda.

## 3. Límites de tiempo de estudio

TiempoU debe permitir establecer un límite general de horas de estudio por día.

Este límite representa el máximo de tiempo total que el estudiante desea dedicar al estudio durante una jornada, considerando todas sus actividades.

También se permite establecer un límite particular para una actividad.

### Reglas

- El límite general funciona como un máximo global diario para la suma de las sesiones de todas las actividades.
- El límite particular establece un máximo diario adicional para la actividad correspondiente.
- El límite particular puede ser inferior al límite general, pero nunca permite superar el límite global.
- Cuando una actividad no tiene un límite particular, queda sujeta al límite global diario.
- La suma de todas las sesiones de un día no debe superar el límite global ni el tiempo total realmente disponible.
- Ninguna sesión puede superar el tiempo disponible del intervalo correspondiente.
- Los límites sirven para organizar las sesiones y no modifican directamente el esfuerzo total estimado de una actividad.

## 4. Generación automática de sesiones

TiempoU debe generar sesiones de estudio a partir de:

- Las actividades pendientes.
- El esfuerzo estimado de cada actividad.
- La fecha y hora de entrega.
- La disponibilidad registrada.
- Los límites de estudio.
- El orden de prioridad calculado por el motor IPA.

El sistema debe distribuir el esfuerzo estimado en sesiones dentro de los intervalos disponibles antes de la fecha y hora de entrega.

### Reglas

- Las sesiones se generan automáticamente cuando existe disponibilidad.
- Se debe respetar la fecha y hora de entrega de cada actividad.
- No se deben programar sesiones después de la fecha y hora de entrega.
- No se deben programar sesiones en días u horarios sin disponibilidad.
- La distribución debe respetar el límite global diario.
- También debe respetar los límites particulares establecidos para cada actividad.
- Se debe intentar atender primero las actividades de mayor prioridad.
- Una actividad puede dividirse en varias sesiones.
- La suma de las duraciones planificadas debe corresponder al esfuerzo estimado, salvo que la disponibilidad y los límites impidan completar la distribución.

Cuando no exista tiempo suficiente para distribuir todo el esfuerzo, la aplicación debe mostrar una advertencia indicando que la planificación no alcanza a cubrir las horas estimadas.

La aplicación no debe modificar silenciosamente el esfuerzo estimado para ocultar esa insuficiencia.

## 5. Edición de sesiones

El estudiante debe poder modificar la cantidad de sesiones asignadas a una actividad.

También debe poder ajustar la distribución de las sesiones cuando necesite organizar mejor su tiempo.

Cuando se modifica la cantidad de sesiones:

- Se conserva el esfuerzo estimado total de la actividad.
- Se recalcula la duración de las sesiones.
- Se respetan los días restantes hasta la entrega.
- Se respetan los intervalos de disponibilidad.
- Se respetan el límite global diario y el límite particular de la actividad, cuando exista.
- Se actualiza la planificación de esa actividad.

La edición no debe generar sesiones que excedan la disponibilidad registrada ni los límites establecidos.

Si la nueva distribución no es posible, se debe informar al estudiante y conservar una planificación válida.

## 6. Reorganización de sesiones

Las sesiones futuras deben poder reorganizarse cuando cambien las condiciones de planificación.

Situaciones que requieren actualización:

- Modificación de la disponibilidad.
- Cambio del esfuerzo estimado.
- Cambio de fecha u hora de entrega.
- Modificación del límite global diario.
- Modificación del límite particular de una actividad.
- Cambio de prioridad que afecte la distribución.
- Modificación manual de la cantidad de sesiones.

La reorganización debe considerar los días y horarios restantes hasta la fecha y hora de entrega.

Las sesiones que ya fueron marcadas como realizadas deben conservarse y no deben volver a generarse como pendientes.

Las sesiones futuras pueden redistribuirse según la nueva disponibilidad y los límites vigentes.

La reorganización no debe duplicar sesiones realizadas ni generar sesiones fuera de los intervalos disponibles.

## 7. Seguimiento de sesiones

Cada sesión debe tener un estado:

- Pendiente.
- Realizada.

El estudiante podrá marcar una sesión como realizada desde el detalle de la actividad.

### Interfaz de seguimiento

Para evitar que la lista general de actividades se vuelva demasiado extensa, las sesiones no deben mostrarse todas directamente en la pantalla de inicio.

Al ingresar al detalle de una actividad, se podrá abrir una ventana o modal con:

- Esfuerzo estimado.
- Número de sesiones planificadas.
- Fecha y duración de cada sesión.
- Estado de cada sesión.
- Acción para marcar una sesión como realizada.
- Acción para editar la distribución.

El seguimiento debe ser sencillo y no requerir registrar información adicional innecesaria.

## 8. Relación entre sesiones y actividades

Cada sesión pertenece a una actividad.

Cuando una actividad cambia de estado, la planificación debe actualizarse de la siguiente manera:

### Actividad Entregada

- Deja de participar en la planificación futura.
- Sus sesiones pendientes dejan de programarse.
- Se conservan las sesiones que ya fueron registradas como realizadas.
- Las sesiones realizadas permanecen disponibles en el detalle de la actividad como historial.

### Actividad No entregada

- Deja de participar en la planificación futura.
- Sus sesiones pendientes dejan de programarse.
- Se conservan las sesiones que ya fueron registradas como realizadas.
- Las sesiones realizadas permanecen disponibles en el detalle de la actividad como historial.

### Actividad reactivada

- Vuelve a participar en la planificación de actividades pendientes.
- Se genera una nueva planificación considerando el tiempo disponible hasta su fecha y hora de entrega.
- Se conservan las sesiones que ya fueron registradas como realizadas.
- Las sesiones realizadas no deben duplicarse ni volver a aparecer como pendientes.
- La nueva planificación debe considerar el esfuerzo que todavía falta por cubrir, descontando el tiempo correspondiente a las sesiones realizadas.
- Si no queda tiempo disponible antes de la entrega, no se generan sesiones y se informa al estudiante.
- La nueva planificación debe respetar la disponibilidad, el límite global diario y el límite particular de la actividad, cuando exista.

### Actividad eliminada

- Se eliminan sus sesiones asociadas.
- No deben quedar registros huérfanos.

### Materia eliminada

- Se eliminan las actividades y sesiones asociadas.
- No deben quedar registros relacionados con la materia eliminada.

## 9. Ausencia de disponibilidad

Cuando el estudiante no haya registrado intervalos de disponibilidad:

- La aplicación continúa funcionando.
- El motor IPA utiliza D=0 y R=100, según su especificación.
- No se generan sesiones automáticamente.
- Se informa al estudiante que debe configurar su disponibilidad para utilizar la planificación de sesiones.

La ausencia de disponibilidad no debe bloquear la creación, edición o priorización de actividades.

## 10. Datos que debe mostrar la aplicación

La sección de disponibilidad debe mostrar:

- Los días de la semana.
- Los intervalos libres registrados.
- El límite global diario.
- La opción para guardar los cambios.

El detalle de cada actividad debe mostrar:

- Esfuerzo estimado.
- Cantidad de sesiones.
- Distribución por fechas.
- Duración de cada sesión.
- Sesiones realizadas y pendientes.
- Advertencia cuando no exista tiempo suficiente para completar el esfuerzo estimado.

## 11. Restricciones de implementación

- No utilizar servicios externos para generar sesiones.
- No utilizar bases de datos ni almacenamiento persistente.
- La disponibilidad y las sesiones se mantienen en memoria durante la sesión de uso.
- La generación y reorganización deben implementarse mediante funciones independientes de la interfaz.
- Las sesiones deben estar relacionadas con su actividad mediante identificadores.
- No duplicar sesiones realizadas.
- No generar sesiones fuera de los intervalos disponibles.
- No superar el límite global diario ni los límites particulares de las actividades.
- No modificar automáticamente las notas ni los estados de entrega de las actividades.
- Al entregar o marcar como no entregada una actividad, deben dejar de programarse sus sesiones pendientes y conservarse las realizadas.
- Al reactivar una actividad, debe generarse una nueva planificación sin duplicar las sesiones realizadas.

## 12. Casos de prueba

### Prueba 1: disponibilidad semanal

Registrar intervalos en varios días y comprobar que se guardan correctamente.

### Prueba 2: varios intervalos en un día

Registrar dos intervalos separados en un mismo día y comprobar que ambos se reconocen.

### Prueba 3: intervalo inválido

Intentar registrar una hora de inicio posterior a la hora de finalización. El sistema debe impedirlo.

### Prueba 4: generación automática

Crear una actividad de cuatro horas y configurar disponibilidad suficiente antes de su fecha de entrega. El sistema debe distribuir las sesiones.

### Prueba 5: disponibilidad insuficiente

Crear una actividad cuyo esfuerzo estimado supere el tiempo disponible. El sistema debe mostrar una advertencia sin modificar el esfuerzo estimado.

### Prueba 6: límite global diario

Configurar un límite global diario y comprobar que la suma de las sesiones de todas las actividades no lo supera.

### Prueba 7: límite particular

Establecer un límite particular inferior al global para una actividad y comprobar que se respeta sin permitir que la suma diaria supere el límite global.

### Prueba 8: edición de sesiones

Modificar la cantidad de sesiones y comprobar que la distribución se actualiza sin cambiar el esfuerzo estimado total.

### Prueba 9: marcar sesión realizada

Marcar una sesión como realizada desde el detalle de una actividad y comprobar que conserva su estado después de reorganizar las sesiones futuras.

### Prueba 10: ausencia de disponibilidad

Eliminar todos los intervalos y comprobar que no se generan sesiones, pero que la aplicación continúa funcionando.

### Prueba 11: cambio de disponibilidad

Modificar los intervalos, guardar y comprobar que se actualiza la planificación futura.

### Prueba 12: eliminación de actividad

Eliminar una actividad y comprobar que desaparecen sus sesiones asociadas.

### Prueba 13: actividad entregada o no entregada

Cambiar una actividad a Entregada o No entregada y comprobar que sus sesiones pendientes dejan de programarse, mientras las realizadas se conservan.

### Prueba 14: reactivación de actividad

Reactivar una actividad y comprobar que se genera una nueva planificación con el tiempo restante hasta la entrega, conservando las sesiones realizadas y sin duplicarlas.

## 13. Estado de aprobación

Este documento define las reglas de disponibilidad, generación automática, edición, reorganización y seguimiento de sesiones de estudio.

Su implementación debe mantener coherencia con el modelo de datos, el motor IPA y las reglas de calificación de TiempoU.
